# Shatter Dungeon

A bouncy-orb roguelite brick-breaker. Aim from the bottom, fire a stream of elemental orbs into descending monster blocks, pick a perk after every floor, and beat a boss every 10 floors to bank your loot.

Built so far: the core run loop (milestone 1), permanent progression between runs (milestone 2: forge, tavern, talent tree) the simulated store (milestone 3: chests and orb merging, energy, season pass, gem packs) the Weekly Tower with a leaderboard server (milestone 4) and the native iOS and Android wrap with RevenueCat purchases and AdMob ads (milestone 5). The native apps are wired but not released: see [NATIVE.md](NATIVE.md) for what is left.

## Run it

```bash
npm install
npm run dev        # http://localhost:5183
npm run dev:lan    # same, reachable from a phone on your network
npm run server     # leaderboard server on http://localhost:8787 (only the Weekly Tower needs it)
```

### Hosted version

The browser build is published to GitHub Pages at `https://<your-github-username>.github.io/shatter-dungeon/`. Every push to `master` runs `.github/workflows/pages.yml`, which runs the tests, builds, and republishes the site; a failing test stops the deploy.

Two things differ from running it locally:

- It is the browser build, so the store and ads are simulated and gems are free. The store screen says so.
- GitHub Pages serves only static files, so the leaderboard server is not there. The Weekly Tower still plays and reports the leaderboard as unreachable, unless the site is built with `VITE_API_URL` pointing at a hosted copy of `server/`.

| Command | What it does |
|---|---|
| `npm test` | Vitest suite for the simulation |
| `npm run typecheck` | TypeScript, strict |
| `npm run build` | Production build into `dist/` |
| `npm run sim` | Headless bot plays seeded runs and prints a balance report |
| `npm run sim -- 100 9` | 100 runs, 9 candidate angles per turn (a sharper bot) |
| `npm run sim -- 100 5 0.5` | The same bot on a profile half way to fully upgraded (0 to 1) |
| `npm run career` | The bot plays 80 runs on one profile, spending coins and talent points as it goes |

| `npm run seed:tower` | Bots play this week's tower and post their runs to the local server |
| `npm run cap:sync` | Build and copy the game into the iOS and Android projects |

## Layout

```
src/sim/        Pure, deterministic game simulation. No DOM.
  run.ts          Turn state machine and combat. Start here.
  physics.ts      Circle-vs-grid collision with a fixed 1/120s step.
  scaling.ts      Every difficulty and economy curve.
  perks.ts        Perk table and the stats derived from it.
  meta.ts         Forge and tavern upgrades, talents, hero levels, and what they add to a run.
  orbs.ts         Orb collection, merging, chest contents and odds.
  energy.ts       Energy that regenerates over time.
  pass.ts         Season pass tiers and rewards.
  store.ts        The player's wallet and everything that pays into or out of it.
  dmath.ts        sin, cos and powers that give the same bits on every JavaScript engine.
  replay.ts       Re-runs a recorded run from its seed and input log.
  tower.ts        Weekly Tower rules: the week's seed, the fixed loadout, scoring.
  elements.ts, affixes.ts, boss.ts
src/view/       Canvas renderer, effects, synthesised audio, HUD, DOM screens (hub.ts: forge, tavern, talents; store.ts: store, orbs, pass, energy).
src/platform/   The one interface for purchases and ads: simulated in a browser, RevenueCat and AdMob in the app.
src/storage.ts  Keeps a second copy of the save in the device's own storage in the app.
ios/, android/  Native projects generated by Capacitor.
src/net/        Client for the leaderboard server.
server/         Leaderboard server: api.ts (plain request handlers), store.ts, main.ts (node:http).
src/main.ts     Wires it together.
scripts/        Balance bot (sim.ts), career simulation (career.ts), shared bot logic (bot.ts).
tests/          Simulation tests.
```

The simulation never touches the DOM or the clock and takes all randomness from a seed, so the same seed and inputs always replay identically. `new Run(structuredClone(run.s))` gives an independent copy, which is how the bot looks ahead.

## Progression

Coins kept from a run are spent on the title screen. A boss kill banks everything carried; dying before one keeps a quarter.

- **Forge** (8 upgrades) strengthens the orbs: damage, crits, bounces per orb, and one mastery per element.
- **Tavern** (5 upgrades) strengthens the hero: health, breach armour, healing per floor, coin gain, and the share of unbanked coins kept.
- **Talents** (15 talents in three branches, 26 ranks) are bought with talent points. Each hero level gives one point, and XP comes from floors cleared (10 each) and bosses beaten (50 each). Resetting talents is free.

A run copies the profile when it starts (`new Run(seed, meta)`), so the simulation stays deterministic. All the numbers are in `src/sim/meta.ts`. The save file keeps its original localStorage key and older saves load with empty progression.

## Store, orbs, energy and pass

- **Orbs.** Chests hold orbs of the five kinds. Three of a level merge into one of the next (up to level 7), and the best orb of each kind adds 10% hit damage per level to that kind in every run.
- **Chests.** Wooden (2 orbs, 2,500 coins), Silver (5 orbs, 100 gems), Golden (10 orbs, 300 gems). Every boss beaten drops a Wooden Chest, and a rewarded ad gives one up to three times a day. Drop rates are shown in the store and defined in `CHESTS`. Rolls use a seed kept in the save, so reloading cannot reroll a chest.
- **Energy.** A run costs 1 of 5 energy; one comes back every 20 minutes. Out of energy, the player can refill for 40 gems, watch an ad for one point, or wait.
- **Season pass.** 20 tiers of 250 XP in four-week seasons, with a free and a premium reward on each tier. Pass XP is the same XP a run gives the hero.
- **Products.** A one-time starter pack, three gem packs and the premium pass, listed in `PRODUCTS` in `src/sim/store.ts`.

None of this logic reads the clock or the platform itself: the time is passed in, and a purchase is granted only after `Platform.purchase` resolves.

## Weekly Tower and leaderboard

Each week (Monday 00:00 UTC) has one tower seed. Every player climbs it with the same fixed loadout (`TOWER_META`, a half-upgraded profile) and one life, so the result depends on play alone. A run costs 1 energy and earns XP but no coins or chests. The best floor of the week counts, with blocks shattered as the tie-break.

Scores are not trusted from the client. A run records its inputs (`run.log`), the game posts that log, and the server replays it with the same simulation code to work out the floor itself (`server/api.ts`, `src/sim/replay.ts`). For that to work the simulation must give identical results everywhere, which is why it uses `dmath.ts` instead of `Math.sin`, `Math.cos` and `Math.pow`.

- **`SIM_VERSION`** (`src/sim/tower.ts`) must be bumped whenever a change alters how a run plays out. A test replays a recorded reference run and fails when the rules drift; the game also checks that reference before posting, so a browser that computes differently does not send scores that would be rejected.
- **Identity** is a random id kept in the save plus a display name. There are no accounts, so clearing the browser's storage starts a new leaderboard identity.
- **Offline**, the tower still plays. A new best is kept in the save and sent the next time the server answers.
- **Limits**: 12 submissions a minute per address, 512 KB per request, replays capped at 1.2 million steps. Names are stripped to letters, digits and a few symbols; there is no profanity filter.

The server has no dependencies beyond Node. `server/api.ts` is plain request-in, response-out functions over a `ScoreStore` interface, so it can be moved behind a serverless function or a database without touching the rules. In development the Vite dev server proxies `/api` to it; a deployed build sets `VITE_API_URL` to the server's address. It has only been run locally.

## Tuning

Change numbers in `src/sim/scaling.ts` (block HP, rows per floor, affix rates, hero damage) or `src/sim/perks.ts`, then run `npm run sim`. With the default bot a new profile's median run ends around floor 12 and about 70% of runs beat the first boss; a half-upgraded profile reaches about floor 19 and a full one about floor 29. Block HP grows 25% a floor up to floor 20 and faster after that (`DEEP_FLOOR`), which is what stops a full profile running away.

Upgrade prices live in `src/sim/meta.ts`. `npm run career` shows how long they last: at the moment the bot fills the talent tree in about 60 runs, buys the last upgrade after about 90, and has every orb at level 5 after about 100 without spending a gem.

## Monetization

Real-money products (starter pack, gem packs, premium pass) and rewarded ads (revive, free chest, energy) all go through `src/platform/platform.ts`.

- **In a browser** `SimulatedPlatform` always succeeds, so nothing is charged and gems are free.
- **In the native app** `NativePlatform` sells through RevenueCat and shows AdMob rewarded ads. It grants nothing the store or ad network did not confirm; with no store configured, purchases are simply unavailable.

The wallet itself still lives in the save on the device. [NATIVE.md](NATIVE.md) covers setup, what remains before release, and the limits of that.

In dev builds, `window.__sd` exposes the live run for poking at from the console.
